# Science and agent-platform peer audit

Inspected 2026-10-18 through the GitHub connector, with one primary-source license compatibility lookup. This is a static source audit. No peer code was installed, executed, imported into OpenHuman, or ported. Test files and workflows below were read; their presence is not a claim that their current CI passes. Effort estimates are engineering estimates for a focused implementation, tests and documentation, not commitments.

## Recommendation

Prioritize **observable provenance with explicit uncertainty** and **resource-aware execution planning**. Both add information OpenHuman can act on without replacing its tool registry, harness or permission model. Use existing owners for orchestration and completion, while treating Markdown methods and profile catalogs as sources of native workflow ideas, criteria and interaction design. Their value does not depend on containing a runtime that can be copied. Retain existing owner boundaries: policy and product composition in OpenHuman; generic lifecycle observation in TinyAgents; bounded native file operations in TinyTools; skill discovery/ranking/install mechanics in TinySkills.

A future science pack should be opt-in and small. A useful first scope is a versioned research record, local dataset profile, exact command/result provenance and a reviewer export. It should use actual installed tools and preserve the distinction between a supplied claim, an observed result, a content hash and a verified conclusion. None of the peer examples supplies a reason to widen the current PR's agent schema or add new agents.

It need not run a new framework or load hundreds of personas. Its first acceptance scenario should include missing data, a changed input revision, a failed computation and a reviewer disagreement; each must remain visible instead of being collapsed into a single success label.

## Candidate inventory, from small details to complete modules

### 1. Record observed provenance separately from inferred edges

**Priority: high. Owner: TinyAgents observation interfaces plus OpenHuman artifact persistence. Effort: medium to large, approximately 4–8 engineering days for a narrow first version.**

K-Dense BYOK records tool starts/ends and builds file edges from declared paths or before/after sandbox snapshots. Its asynchronous scan queue explicitly downgrades attribution when queued work means the scan could include another call's writes. This is a stronger model than attributing every changed file to the most recent tool. The same file documents a baseline race that can miss a first write; observation is intentionally incomplete. [Recorder source](https://github.com/K-Dense-AI/k-dense-byok/blob/6a55f5ce6f4bd9ac7ff75d01ec20d7f27073a9f0/server/src/provenance/recorder.ts)

**OpenHuman comparison:** the `coding_handoff` context packet intentionally contains untrusted reports and grants no evidence authority. The TinyAgents finish-policy work distinguishes actual child tool calls from envelopes. An observational artifact layer could bind those real call IDs to workspace-relative revisions, then add `observed`, `inferred`, `missing` and `stale` statuses. It should not promote a handoff's supplied exit code to runtime verification.

**Smallest implementation:** observe known structural write receipts and existing process results first. Those already provide exact target revisions or actual completion states. Add opaque shell snapshot attribution only as an explicitly partial later feature. A bounded queue, per-run identifiers, cancellation handling and startup-baseline completion must be specified; the peer's unbounded queue and hard-coded tool-name lists should not be copied into the generic vocabulary.

#### Observation is a sequence of different claims

The recorder captures an environment snapshot before a step and can refresh it after a suspected environment change. If that probe fails, it retains the last environment identity. Its hash cache uses file size and modification time to avoid rereading unchanged candidates. Those optimizations are useful, but a retained environment is potentially stale and a metadata cache hit is not a fresh content attestation. The queue is serialized but unbounded in this source. These are reasons to design explicit loss and freshness fields before extending the host observer. [Recorder details](https://github.com/K-Dense-AI/k-dense-byok/blob/6a55f5ce6f4bd9ac7ff75d01ec20d7f27073a9f0/server/src/provenance/recorder.ts)

| Record                              | What it establishes                                                                           | What remains unproved                                                               |
| ----------------------------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Admitted concrete tool start        | A particular target and its pinned arguments entered the executor after policy/wrappers       | Success, a persistent write or a completed external effect                          |
| Successful structural write receipt | The tool reports the published target and before/after revision under its filesystem contract | An unrelated external writer cannot change those bytes afterward                    |
| Captured process completion         | That invocation produced the observed exit state and retained output                          | The test is sufficient, its assertions are valid, or the model's conclusion follows |
| Before/after directory scan         | A difference was visible between two bounded snapshots                                        | Exclusive causation by one queued or concurrent call                                |
| Caller-supplied handoff             | Another actor reports an outcome                                                              | Host observation or independent confirmation                                        |
| Export checksum                     | Included bytes match the manifest used by the verifier                                        | Authorship, trustworthy time, permission to redistribute or successful reproduction |

TinyAgents now records actual target names and argument-sensitive side-effect classification inside admitted execution. Its finish activity intentionally records attempts, including a mutating attempt that later fails; it is not a provenance completion event. A new result observer would therefore need a separate versioned outcome contract. Do not reinterpret the existing set of names as a successful-write ledger. [Current owner type](https://github.com/tinyhumansai/tinyagents/blob/e4021670f652ba0ec59c244aad4f660f216c455b/crates/tinyagents-harness/src/middleware/library/verify_before_finish/types.rs)

**First acceptance boundary:** test a denied packed mutation, a literal read-only preview, an admitted write that fails before publication, an actual write followed by external modification, and cancellation while the receipt queue is full. The first two must not create write receipts; the latter three must retain honest failure, freshness and loss states. A delayed snapshot that includes two tools' writes must not assign both exclusively to the first call. Queue overflow must produce a bounded omission count instead of silently dropping evidence or blocking cancellation indefinitely.

### 2. Export a reviewer package without implying execution or authenticity

**Priority: high after provenance exists. Owner: OpenHuman export/artifact subsystem. Effort: medium, 3–5 days.**

The BYOK export code distinguishes matched historical bytes from current unverified copies, emits a missing-information record and provides a static hash verifier. Packaging does not replay commands. Its Markdown renderer selects a fence longer than any embedded backtick run, a useful small detail for safely presenting captured snippets. The verifier checks relative paths, duplicate entries, symlinks, unexpected files and a byte ceiling. [Export renderer and verifier](https://github.com/K-Dense-AI/k-dense-byok/blob/6a55f5ce6f4bd9ac7ff75d01ec20d7f27073a9f0/server/src/evidence/report.ts)

**OpenHuman comparison:** the existing artifact offload uses scoped blob storage and materializes recoverable tool output. That provides storage but not a portable, source-linked review bundle. A future export should reuse that storage and add an inventory, content revisions, selected raw results, explicit omissions and current-versus-captured identity. It must preserve existing tenant scope and scrubbing rules. A checksum inventory alone is not a signature, proof of a successful rerun, or a license to redistribute data.

**Useful bounded increment:** export selected receipts and artifacts as data with an independent integrity check. Do not embed a runnable recovery script, install dependencies or claim broad RO-Crate provenance conformance merely because a JSON-LD descriptor exists.

#### A useful export is inspectable without running its contents

The peer static verifier bounds individual and aggregate bytes and hashes files incrementally; it checks inventory/path problems before treating a file as an included artifact. The renderer separately marks supplied methods text as an author account. That separation is worth retaining: the command recorded in a report is data, even if it resembles a convenient reproduction command. Its descriptor uses an RO-Crate base context, which does not by itself validate a workflow-specific profile. [Verifier and descriptor construction](https://github.com/K-Dense-AI/k-dense-byok/blob/6a55f5ce6f4bd9ac7ff75d01ec20d7f27073a9f0/server/src/evidence/report.ts)

A first host schema should carry export format version, source run/revision, selected artifact IDs, expected digest and size, capture status, inclusion status, omission reason and verifier version. Keep observed and user-authored narrative in separate fields. Store any redacted copy as a new artifact with a new digest and a relation to the source; otherwise a reviewer cannot tell whether a mismatch is corruption or intentional scrubbing. An optional signature is a separate authenticity feature with its own key and trust policy.

**Acceptance cases:** tamper with one included byte; replace an expected file with a symlink; add an unlisted file; supply two spellings of the same portable path; omit a source because retention expired; and place a long backtick run inside captured output. The verifier should report each condition deterministically, never execute an artifact, and never label a missing item as verified. A deliberately selected incomplete export can be valid as an incomplete package. Cross-tenant artifact IDs must fail before bytes are materialized. A cancelled export must not leave a visible package that appears complete.

### 3. Plan concurrency from effective resources, including zero feasible workers

**Priority: high. Owner: host execution planning; a pure arithmetic helper can be separate from machine probes. Effort: medium, 2–4 days.**

The scientific-agent-skills planner combines effective CPU capacity, memory after reserve, task count and the requested worker ceiling. It can return zero when no worker fits memory. Unknown memory becomes a review-required/conservative plan, while accelerator discovery remains a candidate count with usability unverified. Tests cover cgroup ancestors, scheduler allocations, unknown memory, zero-worker plans and nonexecuting accelerator decisions. [Planner](https://github.com/K-Dense-AI/scientific-agent-skills/blob/a1043ef544e3a100c28e70a736b6cf32554d0677/skills/get-available-resources/scripts/plan_workload.py), [behavioral tests](https://github.com/K-Dense-AI/scientific-agent-skills/blob/a1043ef544e3a100c28e70a736b6cf32554d0677/tests/get-available-resources/test_scripts.py)

**OpenHuman comparison:** a limit on concurrent agents does not describe the memory cost of the compilers, browsers or dataset jobs those agents start. The product's parallel agent limits should be distinguished from the machine's executable workload capacity. This is not a reason for a model to inspect arbitrary process environments or for a tool to change host scheduling policy.

**Smallest implementation:** a typed host resource snapshot and deterministic recommendation with explicit unknown fields and binding limits. Start with CPU/memory and keep probes behind existing OS/platform abstractions. Do not silently convert an unknown capacity or an insufficient-memory result into permission to start one job. Recommendations are estimates; they are not reservations.

#### Resource estimates need freshness and a binding-limit explanation

In the inspected arithmetic, CPU, memory, requested concurrency and task count impose separate ceilings. An unknown-memory branch with a per-worker memory request chooses a conservative ceiling of one and marks the result for review; that is still a recommendation under uncertainty. The default reserve is an explicit policy, not measured free capacity. Accelerator visibility is an upper-bound candidate count; allocation success and usable device memory remain unverified. [Plan construction](https://github.com/K-Dense-AI/scientific-agent-skills/blob/a1043ef544e3a100c28e70a736b6cf32554d0677/skills/get-available-resources/scripts/plan_workload.py)

For OpenHuman, separate three layers: a host-owned resource observation with timestamp and scope; a pure recommendation using declared workload estimates; and actual admission/reservation in the runner. A planner should return every binding limit and the assumptions used. It should not raise the agent's tool capability or silently take control of a machine-wide scheduler. Replanning after memory pressure is different from retrying a job that has already made partial changes.

**Acceptance cases:** a container has many visible CPUs but a smaller effective quota; memory reserve leaves zero feasible workers; memory is unknown; the requested task count is zero; a boolean is supplied where an integer is required; an accelerator is visible but unusable; and the snapshot expires before dispatch. The arithmetic must remain deterministic, overflow-safe and independent of probes. Admission should either refresh an expired observation or record that the plan was advisory. Validate estimates against representative real workloads before claiming fewer out-of-memory failures; no such product benchmark was run here.

### 4. Add a bounded local dataset profile as an optional science capability

**Priority: medium. Owner: optional native analysis tool plus existing host filesystem gate. Effort: medium, 3–6 days for CSV/TSV only.**

The missingness/leakage CLI accepts bounded local CSV/TSV, row and file limits, named group/entity/split/time columns and opt-in identifier disclosure. Its output labels overlap as a possible concern rather than proof of leakage, and absence of overlap as insufficient evidence of independence. The entry point delegates analysis and file checks to distinct modules, so its CLI flags are not themselves evidence that every lower-level boundary is correct. [Audited entry point](https://github.com/K-Dense-AI/scientific-agent-skills/blob/a1043ef544e3a100c28e70a736b6cf32554d0677/skills/exploratory-data-analysis/scripts/missingness_leakage_audit.py)

**OpenHuman comparison:** structural source tools already establish a useful contract: bounded reads, content revisions, paginated JSON and gate-controlled paths. A dataset inspector can follow that design without inserting statistics or scientific dependencies into `tinytools` itself. Start with counts, missingness and explicit split overlap; defer automatic causal conclusions, model quality labels and clinical interpretation.

#### Lower-level inspection confirms useful limits and exposes remaining work

The delegated common module rejects URLs, traversal, symlink components, nonregular files and multiply linked input files; it checks initial size and writes a bounded strict-JSON result. The tabular reader checks UTF-8, row shape, field length, row/column limits and requested column names. Distinct-value and overlap tracking have their own caps, with lower-bound/truncation indicators. These are concrete mechanisms rather than CLI help claims. [File/report helpers](https://github.com/K-Dense-AI/scientific-agent-skills/blob/a1043ef544e3a100c28e70a736b6cf32554d0677/skills/exploratory-data-analysis/scripts/_common.py), [tabular reader and accumulators](https://github.com/K-Dense-AI/scientific-agent-skills/blob/a1043ef544e3a100c28e70a736b6cf32554d0677/skills/exploratory-data-analysis/scripts/_tabular.py)

Two details need adaptation. The initial file check and later ordinary open do not establish a revision-stable read against a concurrent external writer. The Python CSV helper temporarily changes the process-wide field-size limit and restores it afterward; concurrent users of that shared interpreter would need coordination. A native owner should use bounded descriptor reads and a content identity, with parser state local to the operation. Neither source inspection nor a digest alone proves that a dataset is representative.

| Proposed field                 | Required meaning                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------------------ |
| Source revision and byte count | Exact input identity and amount actually read, with a documented change-during-read result |
| Rows scanned and truncation    | Scope of the analysis; no population denominator inferred from a prefix                    |
| Missingness and cardinality    | Exact within the scan or explicitly bounded/lower-bound estimates                          |
| Split/entity overlap           | A recorded matching predicate and observed overlap, not a universal leakage verdict        |
| Sample/quantile metadata       | Sampling rule, seed or deterministic selection identity, and approximation status          |
| Identifier exposure            | Explicit opt-in; hashes of low-entropy identifiers are still linkable, not anonymization   |

**Acceptance cases:** a growing CSV crosses the byte cap after the initial stat; a quoted field crosses the field cap; a truncated scan hides a late split overlap; columns are duplicated or absent; an entity cardinality exceeds the in-memory cap; invalid UTF-8 appears halfway through; a supplied path traverses a symlink; and the output budget is smaller than the minimum valid report. Every failure must retain a useful bounded diagnostic without emitting raw dataset rows by default. A same-file scan under changed options must produce a different analysis identity even if the source digest is unchanged.

A complete analysis module becomes reasonable only after those contracts exist. Start with one deterministic local format and pure accumulators, then add host gating and UI presentation. Statistical tests, model training and clinical interpretation are separate capabilities with separate validation requirements; they are not implied by a safe file reader.

### 5. Preserve preregistration integrity and distinguish chronology from a public timestamp

**Priority: medium, science pack only. Owner: OpenHuman workflow record or separate pure audit helper. Effort: medium, 2–4 days for a read-only local audit.**

`prereg.sh` records a first Git commit and data blob hashes, then audits registration contents at HEAD/worktree and result-commit ancestry. Its five repository-based regressions cover placeholder/no-placeholder stamping, edited registrations, early outputs and changed raw data. [Audit script](https://github.com/K-Dense-AI/science-superpowers/blob/0374bdf82c2372bdf1667e3c762146c3a29215f5/skills/preregistering-analysis/prereg.sh), [tests](https://github.com/K-Dense-AI/science-superpowers/blob/0374bdf82c2372bdf1667e3c762146c3a29215f5/scripts/test-prereg.sh)

**Adoption constraint:** the script's `freeze` mutates files and creates two Git commits. It is not suitable for a supposedly read-only tool or unconditional onboarding hook. It also documents unsupported whitespace paths. Parallel-branch and uncommitted-output warnings can coexist with an overall zero exit code, and no committed outputs are not proof that a preregistered analysis has run. The first useful port is a read-only structured audit with separate `integrity`, `chronology`, `data_match` and `unverified` fields, not a single success boolean. Local Git ancestry supports local ordering; it is not independent public preregistration or trusted wall-clock evidence.

#### Separate integrity, chronology and independence

The peer audit chooses the file's first history entry as the claimed freeze and permits only the stamp transformation when comparing contents. It checks result ancestry rather than trusting commit dates, which is the right distinction for local ordering. However, a parallel result branch has no established order relative to the freeze, and an absent output commit provides no evidence that an analysis was executed. The shell's final zero exit status can coexist with warnings on those paths. [Audit status calculation](https://github.com/K-Dense-AI/science-superpowers/blob/0374bdf82c2372bdf1667e3c762146c3a29215f5/skills/preregistering-analysis/prereg.sh)

A read-only host result should include the exact repository/HEAD, registration blob, claimed freeze, result paths, inspected history boundary, working-tree state and independent statuses. Shallow history, rename ambiguity and missing objects must be unknown or an explicit refusal. A later optional freeze operation needs a concrete mutation plan for the file and Git index, and a recovery story if the stamp commit fails after the first commit succeeds. It must not accidentally include unrelated staged changes.

**Acceptance cases:** edit registration bytes after freeze; change data without changing its filename; supply a stamp for another commit; use a parallel result branch; audit shallow history; leave uncommitted outputs; and interrupt between the two freeze commits. A well-formed local audit can establish integrity and ancestry while leaving public timestamping and independent preregistration unverified. Changing the terminal label to “passed” must not erase those dimensions.

### 6. Keep verification guidance domain-specific, but let the host decide completion

**Priority: low as code; medium as a narrowly selected skill. Owner: OpenHuman/TinySkills prompt composition. Effort: small, 0.5–1 day with prompt-budget tests.**

The verification skill requires current output, assumptions, effect sizes/intervals and actual artifact inspection before a research claim. The writer's stop hook supplies one bounded completion reminder and refuses to recurse when already inside a stop hook. [Science verification guidance](https://github.com/K-Dense-AI/science-superpowers/blob/0374bdf82c2372bdf1667e3c762146c3a29215f5/skills/verifying-results-before-claiming/SKILL.md), [bounded stop hook](https://github.com/K-Dense-AI/claude-scientific-writer/blob/529b9f73ab4b48925027145800d7b49e96ccfd3c/scientific_writer/core.py)

**OpenHuman comparison:** the current contribution installs a finish policy tied to actual execution attempts and current-revision guidance. Installing another generic stop loop would overlap with that and could add extra turns without new evidence. Select research-specific explanation through a real skill only when requested; keep runtime verification in the existing harness.

The smallest reusable detail is a reminder budget keyed to the current run, not a new autonomous reviewer. A science profile can ask for units, assumptions, uncertainty and inspected figures while the host retains authority over execution and task status. A missing figure should become a concrete unmet requirement; repeating the same reminder should not be treated as new evidence.

**Acceptance cases:** a stop callback is re-entered, a run is resumed with an old reminder flag, a scientific profile is attached to a read-only explanation, and a tool result includes a fabricated “verification passed” sentence. Reminder scope should remain bounded, read-only work should not require irrelevant execution, and supplied prose must not manufacture a host success record. Test the selected profile's instruction length and relevance; the presence of a large catalog does not justify loading it all.

### 7. Clear stale review decisions and persist honest terminal status

**Priority: medium as regression ideas. Owner: TinyAgents lifecycle state and OpenHuman run presentation. Effort: small to medium, 1–2 days.**

Agentic Data Scientist clears a previous review decision before invoking the reviewer and uses distinct state keys for plan and implementation review. Its terminal status requires a nonempty criteria list, preserves unmet criteria/unapproved attempted stages and emits persistence deltas. These are useful examples of avoiding an empty-list success or a stale prior decision. [Review confirmation](https://github.com/K-Dense-AI/agentic-data-scientist/blob/702dee9dfb9e5165ce51b52ad7b7885948df7cd1/src/agentic_data_scientist/agents/adk/review_confirmation.py), [stage orchestration](https://github.com/K-Dense-AI/agentic-data-scientist/blob/702dee9dfb9e5165ce51b52ad7b7885948df7cd1/src/agentic_data_scientist/agents/adk/stage_orchestrator.py)

**Limit:** the decision remains model output; the callback reads a dictionary's truthiness and relies on ADK private invocation/event fields. Do not import this controller. Use generation-scoped typed states and actual task IDs in existing runners, and test reuse, cancellation and missing decisions. A completed-with-warnings label should be driven by the host's evidence model, not by a model-written approval bit.

The output schema advertises a boolean, but the inspected callback retrieves a dictionary and evaluates its exit field by truthiness. A persisted or alternate-path string such as "false" would be truthy at that boundary unless another layer strictly validates it. This is a code-derived integration risk, not an executed peer failure. Also, the terminal classifier correctly refuses empty success criteria, but its summary text can still say all criteria were met when the list is empty because the unmet list is empty. The host should derive both status and presentation from the same typed state. [Callback](https://github.com/K-Dense-AI/agentic-data-scientist/blob/702dee9dfb9e5165ce51b52ad7b7885948df7cd1/src/agentic_data_scientist/agents/adk/review_confirmation.py), [terminal calculation](https://github.com/K-Dense-AI/agentic-data-scientist/blob/702dee9dfb9e5165ce51b52ad7b7885948df7cd1/src/agentic_data_scientist/agents/adk/stage_orchestrator.py)

Use run, task, generation, reviewer and subject-revision identity if a future review record becomes durable. A new attempt should supersede the prior decision only for that subject; it should not silently reset another agent's work. Persist the terminal outcome before presenting it, and distinguish attempt completion, reviewer opinion, unmet criteria and verified results.

**Acceptance cases:** reuse a reviewer after an earlier approval; return no decision; return a string instead of a boolean; cancel while persisting the decision; approve an old file revision; and provide an empty criteria list. None should produce an unqualified verified outcome. A criteria-checker failure must remain visible even if later stages can continue. This is a focused state-model change, not a reason to adopt the peer's entire orchestration framework.

### 8. Scope loop detection to the emitting agent and one invocation

**Priority: medium if existing loop telemetry demonstrates a gap. Owner: TinyAgents. Effort: medium, 2–3 days.**

The peer detector resets buffers per invocation, restricts observation to its own agent, and stops that agent without ending the whole workflow. It uses a bounded sliding character window with conservative repeated-pattern thresholds. [Loop detector](https://github.com/K-Dense-AI/agentic-data-scientist/blob/702dee9dfb9e5165ce51b52ad7b7885948df7cd1/src/agentic_data_scientist/agents/adk/loop_detection.py)

**Adoption constraint:** its private ADK state-saving bridge, broad exception handling and text heuristics are framework-specific. Before implementing anything, compare existing TinyAgents repetition handling on actual traces. A regression proving that repeated child output cannot trip the parent's detector is more useful than another generic detector. Legitimate repetitive code/data must remain possible.

The detector normalizes whitespace and searches repeated substrings within a bounded character window. That makes it sensitive to formatting equivalence rather than task progress. Its source describes a quadratic worst-case search; bounded input prevents unbounded growth but does not establish low per-token cost. The proposed owner check should measure the actual worst permitted window and streaming cadence. [Detector implementation](https://github.com/K-Dense-AI/agentic-data-scientist/blob/702dee9dfb9e5165ce51b52ad7b7885948df7cd1/src/agentic_data_scientist/agents/adk/loop_detection.py)

**Acceptance cases:** a child emits repeated JSON rows; a parent legitimately prints repeated test fixtures; a long repetition crosses streaming chunk boundaries; a new invocation reuses the agent object; two parallel agents emit identical text; and a cancellation arrives while detection runs. Only the intended emitting invocation should be affected. Retain the partial transcript and an explicit stop reason. A heuristic stop is a budget/progress intervention, not proof of unsafe behavior or successful task completion.

An alternative requiring less new machinery is to extend current repetition telemetry with generation/call identity and inspect traces first. If existing TinyAgents limits already contain the observed problem, keep only the regression cases. Any new detector should be independently configurable from model-token and wall-clock budgets so users can distinguish which limit stopped their task.

### 9. Cache skill embeddings by content and model, only if lexical search needs improvement

**Priority: low until relevance is measured. Owner: TinySkills ranking implementation, host-visible corpus unchanged. Effort: medium, 3–5 days plus evaluation corpus.**

The MCP search engine embeds name plus description, lazily loads its model, and caches batches by model name plus exact texts. It verifies the row count of a cached matrix and falls back to re-encoding on load failure. [Search/cache implementation](https://github.com/K-Dense-AI/claude-skills-mcp/blob/72a7b502237cb3e697d3944be1b778498eed2d87/packages/backend/src/claude_skills_mcp_backend/search_engine.py)

**OpenHuman comparison:** `skills/search.rs` already returns a capped projection and delegates ranking to TinySkills while the host selects trusted roots. Keep that split. A vector backend would add model download, disk/RAM and cache-lifecycle costs; the peer's cache only checks one shape dimension and has no eviction budget in this file. Candidate improvements include version/model/content cache identity, validated finite/dimensioned arrays and lexical fallback, not replacing discovery with a new Python service.

The cache concatenates model name and batch texts with a NUL separator. Without an input restriction or length-prefix encoding, delimiter-containing fields can form an ambiguous identity. It also identifies the model by a name rather than an immutable model revision. These are code-derived cache-contract concerns, not measured ranking defects. The existing finite-norm guard in cosine similarity handles zero magnitude; it does not validate a cached matrix's dimensionality, finite values or correspondence to the current corpus. [Cache and similarity source](https://github.com/K-Dense-AI/claude-skills-mcp/blob/72a7b502237cb3e697d3944be1b778498eed2d87/packages/backend/src/claude_skills_mcp_backend/search_engine.py)

**Acceptance cases:** the same model name resolves to a changed revision; two batches contain delimiter bytes; a cache has the correct row count but wrong embedding dimension; a matrix contains NaN; cache writing is interrupted; the model is unavailable offline; and a skill is removed from the trusted corpus while an old index remains. Invalid caches should be discarded, ranking should remain bounded, and fallback results must still respect the host-selected corpus. Measure recall on realistic paraphrases, exact tool names and multilingual queries against the current lexical baseline before accepting the model's storage/startup cost.

### 10. Use document-neutral artifact inventories and narrowly tested metadata parsing

**Priority: medium for artifact UI; low for parser portability. Owner: OpenHuman artifact presentation or a document-specific module. Effort: small to medium, 1–3 days.**

The writer preserves legacy PDF/TeX fields while adding generic final/draft/source/artifact lists and document-neutral aliases. Its tests cover nested-brace LaTeX titles, formatted text in word estimates and excluding BibTeX directives from citation counts. [Models](https://github.com/K-Dense-AI/claude-scientific-writer/blob/529b9f73ab4b48925027145800d7b49e96ccfd3c/scientific_writer/models.py), [scanner/parsers](https://github.com/K-Dense-AI/claude-scientific-writer/blob/529b9f73ab4b48925027145800d7b49e96ccfd3c/scientific_writer/utils.py), [tests](https://github.com/K-Dense-AI/claude-scientific-writer/blob/529b9f73ab4b48925027145800d7b49e96ccfd3c/tests/test_utils.py)

**Adoption constraint:** the peer scanner walks the entire project recursively and the parsers read whole files. OpenHuman should use its existing artifact store, bounded enumeration and host gate. Citation counts are metadata; they do not establish that references exist or support the prose. Regex word counting should remain an explicitly approximate display, not a publication compliance certificate.

Separate artifact identity from its role and readiness. A PDF may be a source reference, draft, figure or final deliverable; an extension does not decide that. The peer retains multiple artifact lists for compatibility and a separate compilation-success flag. A host model should avoid disagreeing duplicated inventories by assigning stable artifact IDs and relations, then projecting legacy fields when needed. [Artifact/result model](https://github.com/K-Dense-AI/claude-scientific-writer/blob/529b9f73ab4b48925027145800d7b49e96ccfd3c/scientific_writer/models.py)

The scanner's “continue the previous paper” heuristic can choose the most recently modified directory when no stronger topic match exists. That is useful as a suggestion but too weak to authorize modification of a document in OpenHuman: bind editing to the selected artifact/workspace or ask for a target when ambiguity remains. [Reference selection and scanning](https://github.com/K-Dense-AI/claude-scientific-writer/blob/529b9f73ab4b48925027145800d7b49e96ccfd3c/scientific_writer/utils.py)

**Acceptance cases:** two documents have similar names; the most recent directory belongs to another scope; one file appears in multiple roles; a final PDF exists but compilation failed; a bibliography contains directives and nested braces; and recursive enumeration reaches its entry budget. Preserve partial enumeration and approximate metadata labels. A citation count must not become a “references verified” badge, and an artifact's final label must not hide missing required outputs.

### 11. Make content identities unambiguous and independent of file enumeration order

**Priority: medium design reference; direct reuse blocked by license assessment. Owner: TinySkills bundle identity. Effort: small, 0.5–1 day for an independently specified contract and tests.**

Multica sorts files by path, includes per-file hashes and sizes, and hashes length-prefixed fields including a version string and source identity. Two tests cover order independence and changed primary content. [Bundle hash](https://github.com/multica-ai/multica/blob/9b43430438e3a2dce63906127d337663cc488c59/server/pkg/skillbundle/hash.go), [tests](https://github.com/multica-ai/multica/blob/9b43430438e3a2dce63906127d337663cc488c59/server/pkg/skillbundle/hash_test.go)

**OpenHuman comparison:** skill install acknowledgements already bind to a document digest. Structural chunks in the current adapter bind both manifest and template content. A multi-file skill format should define canonical paths, duplicate handling, field boundaries and versioning once in its owner. Do not copy Multica's implementation or notices into a GPL component on the assumption that its license is ordinary Apache.

The hash builder's sorted length-prefixed fields prevent ordinary concatenation ambiguity, but the builder itself does not reject duplicate paths; the importer handles collisions elsewhere. An owner contract needs to specify that dependency instead of assuming every caller came through the same importer. Sorting cannot make a duplicate-path bundle unambiguous if a consumer later chooses first or last wins. [Hash construction](https://github.com/multica-ai/multica/blob/9b43430438e3a2dce63906127d337663cc488c59/server/pkg/skillbundle/hash.go)

**Acceptance cases:** reorder a bundle; change only one asset; introduce duplicate normalized paths; use ambiguous concatenation field boundaries; vary line endings; and change source identity without changing bytes. Specify which transformations preserve content identity and which create a new package identity. A stable hash is not an install permission, trusted publisher identity or malware scan. An independently implemented versioned scheme should record its design provenance and avoid copying restricted implementation text.

### 12. Treat archive path normalization and collisions as one contract

**Priority: medium regression inventory; direct reuse blocked by license assessment. Owner: TinySkills installer. Effort: small to medium, 1–2 days if archive import is actually in scope.**

Multica handles Windows backslash entries, directory markers, absolute/drive/NUL paths and collisions after normalization. It accepts a root or single-wrapper skill layout and prevents nested `SKILL.md` files from becoming supporting assets. The importer skips some individually invalid/oversized assets but aborts aggregate cap failures. [Archive importer](https://github.com/multica-ai/multica/blob/9b43430438e3a2dce63906127d337663cc488c59/server/internal/handler/skill_import_archive.go)

**OpenHuman comparison:** the current URL installer fetches a bounded Markdown document through TinySkills scanning and digest acknowledgement. An archive format would be a separate new capability. Reuse the test questions, including platform-independent path interpretation and duplicate canonical names; define whether partial imports are allowed and make omissions visible. Do not add ZIP support merely to match another product.

The importer's compressed-upload ceiling is separate from decompressed per-file, aggregate-byte and file-count limits. It validates paths before selecting the shallowest skill document, and treats normalization collisions as a bundle error. A future TinySkills archive contract should also decide whether multiple competing roots are rejected, and whether portable case-folding or Unicode normalization is part of collision detection. Do not silently depend on whichever filesystem receives the bundle. [Archive selection and limits](https://github.com/multica-ai/multica/blob/9b43430438e3a2dce63906127d337663cc488c59/server/internal/handler/skill_import_archive.go)

**Acceptance cases:** backslash and slash entries normalize to the same name; a drive-prefixed path appears; a compressed entry lies about decompressed size; two candidate roots compete; a nested skill document appears as an asset; aggregate limits are exceeded; and one asset is omitted while primary content remains valid. Reject or explicitly report partial imports according to the chosen policy. An acknowledgement must bind to the actual accepted bytes and omission set; otherwise the user can approve one apparent bundle and install a different one.

### 13. Delimit source text without granting it instruction authority

**Priority: small hardening review. Owner: existing prompt rendering. Effort: small, 0.5–1 day.**

Mimeo sanitizes metadata into a single line, validates wrapper tag names, and breaks matching opening/closing tag sequences inside source text. [Prompt-boundary helper](https://github.com/K-Dense-AI/mimeo/blob/a4cea1842a24515cda354a3aa9eb9763677a3cdd/src/mimeo/prompt_safety.py)

**OpenHuman comparison:** coding handoffs are structured bounded data preceded by an untrusted-report notice. A malicious reference must not gain authority by closing a visual delimiter. Use adversarial rendering regressions where a real renderer needs them. Delimiters do not constitute a security boundary or guarantee that a model ignores embedded instructions. Keep JSON validation, permissions and trusted tool-result evidence separate.

A small additional gap appears at the helper boundary: attribute values are escaped but attribute keys are interpolated. Trusted fixed keys are fine; accepting arbitrary untrusted keys would require its own validation. Tag-name validation permits alphanumeric characters under Python's predicate, so a port should explicitly choose its accepted character set rather than assuming ASCII. [Complete helper](https://github.com/K-Dense-AI/mimeo/blob/a4cea1842a24515cda354a3aa9eb9763677a3cdd/src/mimeo/prompt_safety.py)

**Acceptance cases:** case-varied closing tags, whitespace around delimiters, embedded backticks/newlines in metadata, a quote-bearing attribute value, an untrusted attribute name, and a very long source block. A renderer should remain well-formed and bounded without deleting legitimate source meaning. Most importantly, escaped text remains untrusted data. Admission decisions must continue to depend on the host policy and actual tool arguments, not how convincing the rendered block looks.

### 14. Credential forwarding should be narrowly scoped, but the inspected bridge is not reusable

**Priority: reference only. Owner: OpenHuman runtime host. Effort: small for a regression; no port proposed.**

The DSH bridge builds a fresh environment map containing only a particular task-token class rather than copying a complete parent environment. This illustrates the narrow-interface principle, but its package is explicitly `private` and `UNLICENSED`, with prerelease DeepSeek harness peers. [Task environment](https://github.com/multica-ai/dsh-multica-runtime/blob/e29aae228449dfe50e88af60ef4281e38ca44e2a/src/task-env.ts), [package manifest](https://github.com/multica-ai/dsh-multica-runtime/blob/e29aae228449dfe50e88af60ef4281e38ca44e2a/package.json)

Do not infer authorization from a token prefix alone or copy this source. Use current host credential scoping and test which variables may reach which child tool. No credential values were inspected in this audit.

**Acceptance cases for the existing host:** an unrelated parent variable, a similarly named but unauthorized token, an expired task credential, a child for the wrong task, and a downstream crash that would otherwise print its environment. Only the explicitly granted capability should reach the intended child, and diagnostics should avoid credential values. These tests can be written against the host's public environment-construction contract without inspecting real secrets or importing the private bridge.

The separately inspected Karpathy prompt package illustrates why runtime code is not required for useful inspiration. Its actual guidance and examples support the native-design candidate below. Its skill metadata declares MIT, while the inspected tree lacks a standalone license/notice file; that distinction is retained in the reuse screen.

### 15. Turn a short coding guideline into inspectable native work state

**Priority: medium for design and focused regressions. Owner: OpenHuman task presentation and TinyAgents task/evidence contracts. Effort: 2–4 days for one narrow behavior, not an entire new review system.**

The actual Karpathy skill asks a coding assistant to expose assumptions, avoid unnecessary abstraction, keep edits related to the request and define verifiable goals. Its examples pair a proposed step with a check. These are useful instructions for a human or model, but the package does not implement a runtime that enforces them. [Pinned skill](https://github.com/multica-ai/andrej-karpathy-skills/blob/2c606141936f1eeef17fa3043a72095b4765b9c2/skills/karpathy-guidelines/SKILL.md), [worked examples](https://github.com/multica-ai/andrej-karpathy-skills/blob/2c606141936f1eeef17fa3043a72095b4765b9c2/EXAMPLES.md)

A native interpretation can be more useful than loading another prompt. Represent a task's important assumptions as accepted, unresolved or revised; map each proposed change to a criterion; and attach actual observed evidence to that criterion. Avoid implementing a universal clarification gate: an already authorized, reversible task should proceed with a reasonable stated assumption. A scope view can identify unexplained changes without rewriting or deleting unrelated pre-existing user work.

One worked example claims to test deterministic ordering of equal scores, yet its assertions check only score values. They do not inspect the tied records' identities or order. This is a static assertion-adequacy finding: an implementation that swaps equal-score records could satisfy the displayed assertions. It is not a claim that a peer test suite was run or failed. The example inspires a richer feature: review whether the assertion actually discriminates the behavior claimed by the criterion, using a small counterexample or controlled mutation. [Tie-order example](https://github.com/multica-ai/andrej-karpathy-skills/blob/2c606141936f1eeef17fa3043a72095b4765b9c2/EXAMPLES.md)

**Acceptance cases:** a criterion names tie order but its test checks only scores; a user explicitly authorizes the assumed format; the worktree contains unrelated user edits; a later input changes the criterion; and a check passes against an old revision. The interface should expose the inadequate oracle and stale revision, preserve the accepted assumption and unrelated work, and update only the affected criterion. A shorter diff is not automatically a better solution, and a passing test is not automatically adequate evidence.

At a larger scale, combine this criterion mapping with pstack-inspired exact-head checks, structural edit receipts and research-profile artifact requirements. The same native mechanism can support coding and science without copying the wording of either prompt or importing a second agent framework.

## Implementation order and decision gates

| Increment                       | Concrete deliverable                                                              | Acceptance needed before the next increment                                           |
| ------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Evidence vocabulary             | Separate claim, admitted attempt, observed outcome, revision and omission records | Denied/preview calls cannot create write evidence; stale observations remain stale    |
| Provenance from known outputs   | Bind structural receipts and process completions to scoped run/artifact IDs       | Cancellation, overflow, retention expiry and external modification remain visible     |
| Reviewer export                 | Bounded static package with an inventory and independently checkable hashes       | Tamper, path, omission and redaction tests; no bundled-content execution              |
| Resource planning               | Pure CPU/memory arithmetic over a timestamped host observation                    | Zero and unknown states, stale snapshots and deterministic binding-limit explanations |
| Local dataset capability        | One bounded format with revisioned source and explicit scan limits                | Adversarial parser/containment cases plus honest approximation and disclosure         |
| Optional research workflow      | Selected profiles, typed review state and read-only preregistration audit         | No fabricated authority, stale approval, empty-criteria success or automatic mutation |
| Relevance or document expansion | Measured skill-ranking improvement or a concrete artifact UI need                 | Benefit over current owners exceeds dependency, privacy and migration cost            |

These increments share some record types but should not become one mandatory science framework. Resource planning can stand alone; document inventory should serve non-science artifacts; provenance should support coding and general tool use. Optional scientific guidance should consume those generic records rather than redefine their meaning.

The current source review provides concrete hypotheses and failure cases. It does not measure peer production reliability, validate scientific methodologies across domains, or certify a new OpenHuman module. Whole-module adoption becomes justified only when the narrow contract proves useful and a selected dependency/asset license inventory is complete.
