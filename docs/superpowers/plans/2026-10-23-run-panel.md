# Conversation Run Panel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Organize conversations and give their operators reliable, understandable control of delegated work, communication, recovery, permissions and optional budgets.

**Architecture:** TinyAgents owns generic durable inbox, queue, checkpoint and budget semantics. OpenHuman adapts these contracts to scoped core RPC; React renders the resulting state and never substitutes a ledger status update for execution. Missing owner capabilities must be submitted upstream and available before changing the OpenHuman gitlink.

**Tech Stack:** Rust, TinyAgents, JSON-RPC, React, Redux Toolkit, existing shadcn primitives, userScopedStorage and useT.

**Spec:** `docs/superpowers/specs/2026-10-23-run-panel-design.md` (user approved 2026-10-23).

## Global Constraints

- The existing left sidebar is the conversation dock; the right run panel belongs to the selected conversation.
- Time and token budgets default to Off. Pausing freezes active execution time; children share the conversation token ledger.
- No app restart automatically resumes work. Continue preserves stable identities and sealed transcript generations.
- Runtime configuration applies at safe boundaries. Prompt/tool changes create a successor generation.
- Use shared UI primitives, theme tokens, useT and all 16 locale translations; persist UI preferences through userScopedStorage.
- Preserve protected paths, existing private state and unrelated changes. No automatic replay of uncertain external effects.
- Upstream pushes/PRs and other external mutations require explicit authorization. Prepare reviewable local owner changes first.
- The user explicitly authorized adding and running focused regression tests on 2026-10-23. Use controlled local services; never real provider requests in unit tests.

## Review Focus

- A late response after switching conversations must not change the selected recipient or send its draft elsewhere (Tasks 3, 5).
- Reconnection or double submission must not deliver a message twice (Tasks 1, 3).
- A crash during an external write must preserve an uncertain action instead of replaying it (Tasks 1, 4).
- Parallel children must not each receive the full remaining parent budget (Task 2).
- Continue run must leave independently paused children paused (Task 4).

## Delivery sequence and ownership

There are three separable deliveries: conversation organization, durable execution contracts, then the run panel. Existing bug fixes can continue independently. Do not ship a panel with inert controls while upstream contracts are unavailable.

### Task 1: Durable addressed messages and recovery contract (TinyAgents)

**Files:** Owner modules under `vendor/tinyagents/crates/tinyagents-session/src/run_ledger/command_center/`, `tinyagents-harness/src/run_queue/`, and `tinyagents-graph/src/checkpoint/`.

**Interfaces:** Add an owner-side addressed submission contract with `submission_id`, root session identity, recipient task/session identity, mode (steer/follow-up/answer) and text. Return a durable receipt (queued/delivered/failed). Recipient admission and submission deduplication must be one storage transaction. Reuse the owner's existing message and lifecycle drivers; do not introduce a second execution engine in command-center control.

- [ ] Trace existing message/checkpoint ports and document the exact exported types in the owner's README before editing callers.
- [ ] Implement the missing durable admission and receipt operations in that owner; wire safe-boundary delivery for running and awaiting-input tasks.
- [ ] Make continuation consume the existing checkpoint and task identity. Preserve pending input, committed tool results and uncertain effects across restart.
- [ ] Acceptance: duplicate submission returns the same receipt; wrong-root recipient is rejected; reconnect delivers once; crash/reopen preserves pending input; no completed external action is repeated.
- [ ] Prepare an upstream PR draft and diff locally. After authorization, submit upstream and wait for availability before consuming its gitlink.

### Task 2: Shared optional budgets (TinyAgents plus OpenHuman adapter)

**Files:** Owner `tinyagents-session/src/run_ledger/budget/` (new persisted shared run-budget contract), its driver/schema, and the model-call boundary in `tinyagents-harness`/`tinyagents-runtime`; host `crates/openhuman-core/src/agent/tinyagents/turn_policy.rs`, `agent/session_host/runtime_session/prelude.rs` and `web_chat/ops/turn_guards.rs`.

**Owner trace correction:** Current TinyAgents puts goal accounting in
`tinyagents-harness-tools/src/goals/budget.rs`. Its post-turn charging and
mid-turn projected-spend guard do not reserve shared parallel usage or provide
conversation active-time accounting. Reuse those usage conventions where
appropriate, but keep a conversation budget independent of creating a goal.
The earlier graph/goals and harness/host paths above were planning placeholders,
not existing owner modules.

**Interfaces:** Owner budget snapshot must identify its root session, optional active-time/token limits, consumed and reserved usage, and exhausted reason. Reservation before a model call and usage reconciliation afterward belong to the shared ledger. Host limits are optional; absent limits never create an overall timer.

- [ ] Extend owner budget storage to preserve shared reservations and cumulative consumption over continuation; charge parallel root-tree time once and pause it when execution settles.
- [ ] Integrate model-call reservations with provider usage reconciliation, including retry usage and restart recovery of unresolved reservations.
- [ ] Adapt explicit conversation limits in OpenHuman; expose effective/remaining limits to each child and the model prelude without replacing per-call safeguards.
- [ ] Acceptance: unlimited execution has no overall deadline; parallel children cannot overspend reserved tokens; pause freezes time; extending a limit permits continuation with the same identity.
- [ ] Follow Task 1's upstream publication boundary before host integration.

### Task 3: Scoped run-panel RPC and frontend client

**Files:** `crates/openhuman-core/src/agent_runs/command_center/{mod.rs,schemas.rs}`, new sibling `ops.rs`, `types.rs`; `agent/subagent_host/lifecycle.rs`; `app/src/services/api/subagentApi.ts` and new `runPanelApi.ts`.

**Interfaces:** Host snapshot request takes `threadId`; mutations take `threadId`, exact task/session identity and unique submission id. Snapshot returns revision, root identity, typed task tree, current progress, capabilities, inbox receipts and effective controls. Mutation response is an admission receipt; delivery state arrives through snapshot/events.

- [ ] Resolve root-thread, task, worker-thread and ledger-run identifiers from persisted relationships; reject unowned/cross-root targets in core.
- [ ] Compose the owner's durable messaging/resume contracts with existing subagent lifecycle drivers. Do not call orchestration declaration-only tools or append to the parent composer.
- [ ] Register typed controllers through the existing registry and expose their wire types in runPanelApi using coreRpcClient.
- [ ] Acceptance: running/awaiting/interrupted recipients each accept the correct action; validation failures retain drafts; stale responses retain their original root and revision.

### Task 4: Tree control and effective settings

**Files:** Core `agent_runs/command_center/ops.rs`, `web_chat/session.rs`, `web_chat/types.rs`, `config/schemas/controllers/inference.rs`; TinyAgents prefix-generation and pause/checkpoint ports.

**Interfaces:** Tree actions carry root identity, target subtree, control verb and submission id. Persist pause-group identity; Continue affects only the selected group's descendants. Effective-setting snapshot distinguishes defaults, conversation overrides, pending changes and their boundary.

- [ ] Implement cooperative Pause, immediate Stop with uncertain-effect recording, and scoped Continue through owner lifecycle ports. Persist intent before acknowledging it.
- [ ] Reconcile durable running tasks with live registrations after restart; show absent live workers as Interrupted without automatically spawning them.
- [ ] Refresh cached runtime settings at next turn; explicitly apply prompt/tools via TinyAgents successor-generation refresh, preserving previous generations and respecting revoked tools.
- [ ] Acceptance: independently paused children stay paused; queued work retains order; a restored child reports to its original parent; directory changes never move an in-flight command.
